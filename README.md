# 字幕交付采录台

后期团队从本地字幕编辑器导出的工程包采录媒体版本、语言轨与逐句时轴；独立审校系统记录问题定位、严重度与修订；语言交付系统冻结轨摘要和客户回执。跨语言对齐检查段落数量与时间漂移，客户授权系统核对语言范围和使用窗口。任一时轴、审校、对齐或授权证据不足都会改变交付结论，授权撤销还会把已交付包转入待回收。

入口 `track-import`、`review-decide`、`alignment-evaluate`、`rights-register`、`delivery-evaluate`、`rights-revoke` 均接收 `--db ledger.db export.json`。顶层 JSON 含 `version`，桌面导出的原始字节和 SHA-256 存在 SQLite，报告输出来源、持久化实体和业务决定。每条交付轨必须有通过的审校记录；新审校可通过 `supersedes` 解决同轨旧问题，但不能省略旧问题的证据。三语言及以上交付要求对齐关系连通全部轨道。测试涵盖媒体错版、负时长/重叠、严重意见未关闭与修订恢复、三语言对齐缺口、缺审校、缺语言、授权禁发期、过期、撤销和错版回执。

运行：`python -m pip install . --no-deps --no-build-isolation`，`python -m subtitlehandoff demo`，`python -m subtitlehandoff --help`，`python -m pytest -q`。所有演示和测试使用虚构本地文件，不访问网络。

增强素材新增 `archive-backup` 与 `archive-restore`，把离线工程备份扩展为三盘分片归档：每个工程版本分成两份数据片和一份异或校验片，按任务建立时锁定的盘名册（盘身份→片号）写入三块轮换移动盘，每片附工程版本、片号、长度、文件摘要和各盘实际写入回执。备份区分已写完片、已校验片和已提交世代：片与提交回执落盘后须在后续挂载的重核阶段验证摘要才升为已校验；至少两块盘留有已验证提交回执，世代才算已提交（仲裁数 2/3）。局部重试重放同一请求只沿状态机续走，不会产生新世代；同名不同正文按 `identity_conflict` 拒绝，原始 v1/v2 记录不被覆盖。

任意一盘遗失时，只有剩余片属于同一完整已提交世代且摘要验证通过才可恢复原字节；缺一片由校验片异或重建并回验整文件摘要，两片缺失或剩余片分属不同世代只能待核。提交回执只有写入完成而未验证时，恢复退回上一个可恢复世代或待核，不再读取 SQLite 中的 base64 正文。用途在任务建立前锁定：`disaster_recovery` 凭同世代任意两片重建；`preservation` 还要求三块盘的签收回执都在案，缺一份即待补签收，即使技术上能重建文件，也不能断盘后改名规避。恢复证明列出实际用了哪些盘、哪些片被校验片重建、为何没有选择更新的未提交世代；报告新增 `archive_recovery` 段，回读每个工程版本的可恢复性与保全证据缺口。空文件、末片不满、盘符改变（按盘身份而非挂载点核对）与重复导入都有确定结果。合成样例与字段说明见 `samples/`，场景测试见 `tests/test_archive.py`。
