# 预览缓存清理与任务准入：字段与语义说明

本文件描述 `cache-import`（v2 清单）与 `cache-prune`（可执行准入请求）认识的全部
字段、持久化表和结论由来。所有金额单位为 MB（清单申报值，用于规划），真实文件字节
仅在执行阶段从磁盘读取并作为释放证据落账。

## 1. 缓存清单 `desktop_preview_cache`（v2）

顶层字段：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `version` | 是 | 清单版本，非空字符串。v1 仅 `id/size_mb/last_used`，保持只记录、不可执行。 |
| `cache_root` | v2 必需 | 缓存根目录绝对路径。任何待移走文件解析后必须仍位于该目录内。 |
| `rows[]` | 是 | 缓存节点行，字段见下。 |
| `references[]` | 否 | 活动审校引用事实，独立于后续 prune 请求持久化。 |
| `outside_cache[]` | 否 | 缓存目录外的耐久工程归档；登记为受保护对象，永不成为清理目标。 |

`rows[]` 行字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 缓存节点标识（波形/缩略图/合成预览等）。 |
| `path` | 相对 `cache_root` 的实际文件路径。缺失则该行不可执行。 |
| `sha256` | 文件摘要。执行前逐字节复核，摘要变化即停步并按残存文件重算。 |
| `size_mb` | 申报占用（MB）。 |
| `physical_id` | 物理身份。同内容不同名的记录共享同一身份，磁盘字节只计一次。缺省时由 `sha256` 派生 `phys:<digest前16位>`；v1 行派生 `legacy:<id>` 且不可执行。 |
| `depends_on[]` | 生成依赖的父节点 id。父被清掉后，子缓存即使数据库状态未变也视为不可直接命中。 |
| `gen_cost_seconds` | 重新生成该节点的耗时（秒），用于在可执行序列中选重算总耗时最短者。 |
| `last_used` | 最后使用时刻（ISO-8601），v1 兼容字段。 |
| `durable` | 为真表示耐久工程归档，强制保护、不可淘汰。 |

`references[]` 字段：`id`、`target_id`、`session`、`active_from`、`active_until`。
规划时刻 `at` 落在 `[active_from, active_until)` 内的引用为活动引用：被引用节点、
其全部祖先依赖（保证可观看）及其派生下游（保证一致性）组成保护闭包，prune 不得选择。

## 2. 准入请求 `desktop_cache_prune`

| 字段 | 说明 |
| --- | --- |
| `version` / `request_id` | 版本与请求幂等键。重放同一 `request_id` 直接回读已存结论，释放空间不重复计账。 |
| `mode` | `online_review`（在线审校，默认 180 秒可看时限，优先保留当前场景）或 `night_batch`（夜间批处理，无时限，按下一批输入保护）。 |
| `at` | 规划时刻，用于判定活动引用窗口与任务开始时刻。 |
| `cache_root` / `evict_root` | 缓存根与移走目标根。`evict_root` 必须位于缓存根之外，否则拒绝执行。 |
| `quota_mb` | 磁盘配额。序列每一步（含生成临时峰值）占用都不得超过它。 |
| `protected[]` | 请求级强制保留节点（如夜间批处理的下一批输入 B），并入保护闭包。 |
| `tasks[]` | 下一个预览任务，最多两个；字段见下。 |
| `execute` | 缺省/假：只规划并回读；真：按计划逐步核对磁盘后真实移走与生成。 |

`tasks[]` 字段：`id`、`start_at`（开始时刻，任务按此时刻排序）、`inputs[]`（任务输入
节点，必须在生成时仍在）、`temp_mb`（生成期间额外临时空间，生成结束即释放）、
`gen_cost_seconds`、`deadline_seconds`（在线模式缺省 180）、`output`
（`id/path/size_mb/depends_on`；若该输出已是健康缓存节点则零重算并被保护）。

## 3. 规划与执行语义

1. **依赖先后**：子节点先于父节点移走；任务生成时其 `depends_on/inputs` 必须在场。
2. **物理去重**：占用按 distinct `physical_id` 求和；同一身份的多个命名副本全部移走才
   释放一次字节，`cache_release` 每个身份仅一行。
3. **活动引用**：保护闭包内节点不可选；清掉父资产会令下游缓存失效。
4. **临时峰值**：生成时刻占用 = 在场物理占用 + `temp_mb`。终态合格但中途超盘同样判失败。
5. **序列选择**：对 ≤10 节点、≤2 任务穷举全部合法删除/重算顺序，先比总重算耗时，再比
   最大占用，再按节点名确定性排序。
6. **失败结论**：无法启动时返回 `待空间`，给出 `shortfall_mb`（最少缺的峰值空间）与
   `blocking_step`（阻碍步骤：配额峰值或重算时限）。
7. **执行前核对**：每步重新扫描缓存根，确认目标文件仍在根内、摘要未变、无未申报新增
   占用；出现新增占用立即停步（外部状态不可由台账推断）。
8. **外部改写/移走失败**：标记问题、丢弃受影响记录、用实际残存文件重算后续计划
   （最多 3 次），已完成步骤与释放证据保留。
9. **真实落账**：仅 `shutil.move` 成功且复扫确认文件消失后才写 `cache_release.bytes`；
   重放同一请求不产生第二条释放记录。

## 4. SQLite 持久化（`store.py`）

| 表 | 内容 |
| --- | --- |
| `cache_physical` | 物理身份、摘要、申报大小与首见节点。 |
| `cache_dependency` | 子→父生成依赖边。 |
| `cache_reference` | 活动审校引用及其有效窗口。 |
| `cache_plan` | 每个请求的模式、配额、状态、尝试次数与计划正文。 |
| `cache_plan_step` | 计划/执行步骤（evict/generate）与状态。 |
| `cache_release` | 真实移走证据：物理身份、原路径、落点、实际字节、摘要，按请求+身份+路径唯一。 |
| `cache_task_admission` | 每个任务的准入结论、时限、所需重算秒数与阻碍细节。 |
| `preview_cache` / `cache_prune` | 既有台账表，v1 旧行为不变。 |

状态词：`已缓存`、`已归档`、`已淘汰`、`已规划`、`可启动`、`待空间`、`已执行`、`已中断`。

## 5. 报告回读（`report.py`）

`report` 输出新增 `admissions[]`，每个请求一条，包含：模式与配额、最终状态与原因、
峰值占用、缺额、重算耗时、阻碍步骤、当时生效的活动引用、全部计划步骤、真实释放证据
与逐任务准入结论。配合既有 `entities` 中的物理身份/依赖表，可完整回读每个准入结论的
由来。
